# Execution and performance protocol

The public code is byte-identical to the final run's source files. Earlier experiment-specific implementations are separately preserved inside sealed inputs. There is no algorithm refactor or new fitted model in this release.

For a target kind k and source view v, compute the mean of all target token log probabilities. The risk is `(1-alpha)*mean(original) + alpha*mean(user_masked) - mean(observation_masked)`. The name axis uses alpha 1; the argument axis is full-call risk minus name risk, both at alpha 2. These are normalized risk statistics, not probabilities or independent suffix likelihoods. Scope/Schema precede routing. Mutations require publicly present critical arguments. Discovery is allowed only under the configured scope and output contract. Unknown operations remain protected. The offline oracle never grants runtime authority.

## Actual timing boundaries

- Hardware: two Tesla T4 devices; independent NF4 Qwen7B replicas, no tensor parallelism. Host and software measurements are included in the raw environment reports. The local RTX4060 numeric test is a separate software check and supplies no T4 performance claim.
- Main scoring uses batch size 1, serial original / observation-masked / user-masked views. Name log probabilities are sliced from the complete-call forward only after exact BPE prefix checks. This reduces six separate-target forwards to three. No deployment shared-KV optimization or generation-score reuse is enabled; `use_cache=False` in the full-context scoring backend. Model weights and tokenizer are already loaded.
- `DeploymentScorer.score` synchronizes the selected GPU before measurement and after scoring. The preparation interval covers target tokenization and boundary checks; the forward interval covers the teacher-forced model calls and log-prob extraction; total is their combined elapsed wall time. It also records physical input tokens, batch shapes, and GPU memory peaks. Disk/model download and loading are outside this interval.
- Generation is measured separately with preprocessing, synchronized forward/decode and total intervals. End-to-end proposal timings include input preparation, generation when applicable, guard decision and local simulated dispatch. L reuses historical proposals and records zero new generation calls. R generates independent trajectories; never add its generation timings to L as though L were regenerated.
- Dedicated calibration preflight: 12 proposals, two warm-ups, five timed repetitions per method/proposal, randomized order with fixed timing seed 2718. Ratios are paired by proposal/repetition and aggregated as defined in `preflight_paired.csv`. Main collection performs its recorded model warm-up and health checks before collecting data; main per-event latency is a single observation, not five repeated measurements.
- Latencies are summarized by median and empirical linearly interpolated P95. The one-event workspace P95 equals that observation. Ratios around 1.95–1.96 apply to matched six-forward versus three-forward checks on T4, not arbitrary agents or hardware. Absolute median protected-probe costs are approximately 2.490 s (conditional), 7.992 s (InjecAgent), and 17.946 s (one workspace event).
- Scoped discovery uses zero extra probe forwards, but its parsing/Schema/routing and ordinary generation still have cost. Do not describe zero probe forwards as zero end-to-end latency. No real external tools execute.
