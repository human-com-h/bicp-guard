# Contributing

Report reproduction issues with release tag, OS/Python, command, relevant dependency/GPU versions, and a small redacted error log. Do not attach tokens, private benchmark extensions, manuscript drafts or reviewer correspondence. Report sensitive exposure privately through GitHub's available security reporting mechanism rather than a public issue.

Ordinary changes should include a focused regression check and CHANGELOG entry. Frozen scientific source and policy are checksummed: changing them requires an explicit new experiment/protocol version, provenance update and result comparison. Never retune using the viewed 922 benchmark or overwrite accepted outputs.

Before review, run the Quick Start tests and publication audit. New dependencies and file formats need an explicit reason, source and license. Update the reviewed file inventory after inspection; do not disable its failure merely to pass CI. Full model runs require separate suitable hardware and fresh output paths.
